## 发布前剩余事项

- 本仓库没有自己的 LICENSE 或明确的版权归属声明。由权利人确认是否可公开及采用的许可证后再补充；不能把 NSH 的 Apache-2.0 自动当成本基准的授权。
- NSH 本地源码带有 Apache-2.0 许可；这次没有完成全部传递依赖与分发产物的许可证审计。分发源码、补丁、打包二进制时需按实际内容整理归属和许可证材料。
- 原始内部历史包含内部地址和标识。维护者随后授权重新整理 GitHub 历史：已在独立副本中将当前文件整理为全新初始提交，移除原提交链中的内部地址、项目名和应用 ID；初始提交保留维护者身份及邮箱，提交说明使用英文。内部仓库继续保留原历史。以后不要将内部旧分支或标签直接推到 GitHub，以免重新引入这些内容。
- 新公开仓库的作者 / 提交者身份与邮件应由发布者确认。本次按维护者明确指示仅替换 GitHub 的 main，不修改内部仓库历史。
- 发布前对最终导出目录运行专用 secret scanner，并核对新加入的文件、日志、绝对路径和生成产物。
- README、完整报告与原始 JSON 可以作为候选发布材料；不要包含构建缓存、vendor、诊断工具缓存、桌面截图或未筛选日志。

Git 历史重写不保证清除托管平台已缓存的旧提交、已存在的克隆或派生仓库；若需要清除 GitHub 缓存，应通过 GitHub Support 进一步处理。

## 用于持续性能测试

使用固定源码、Cargo.lock、NSH commit 与补丁；保留环境、版本和原始 JSON。`scripts/run.sh` 现在会记录 metadata、保留完整运行日志，并在异常退出、超时或结果缺失时失败。`scripts/report.py` 拒绝空数据和运行次数 / 阶段不一致的数据；有 metadata 时核对完整文件集合。

标准基线使用完整阶段时长，至少 3 次交错运行；quick 只做流程验证。升级 NSH 时先适配 API 并记录更换前后版本，再比较同机器、同显示条件的结果。不要混合不同硬件、版本、计时口径或受干扰轮次来声称框架优劣。待分析问题见 [性能任务清单](PERFORMANCE-ISSUES.md)。
